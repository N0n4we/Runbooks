# 多参考图 in-place 编辑：结构化提示词

适用于 `BriaFibo2Pipeline`（Fibo 2.0 Edit Turbo，服务端 4 步、`guidance_scale=1.0`，无 mask、无 negative prompt）。
目标同样是「只改指定的东西，其余按原图保留」；但 Fibo2 的**默认行为是重新构图**，所以提示词的写法与 Qwen 那条链完全不同：
身份靠图片，构图靠结构化 caption 按住。

## 1. 模型怎么看你的输入

- 每个 `--images` 依次变成 `<image_1>`、`<image_2>`……；`<image_1>` 是画布，其余是参考。
- Fibo2 的 checkpoint 只用英文训练，**提示词写英文**；中文自然语言多图指令更容易被当成「按参考图重新构图」。
- 提示词按 **VGL JSON** 组织，由 `BriaFibo2Pipeline._parse_prompt` 拆成两部分：
  - `structured_caption`：描述**结果图**长什么样（谁、什么姿势、什么环境、什么光、什么画风）。这是把机位和姿态按回原图的关键。
  - `edit_instruction`：描述**改什么、保留什么**。
- 服务器 `jobs/<job_id>/request.json` 里的 `encoded_edit_prompt` 可以核对这两段是否被正确解析（caption 放顶层或放 `structured_caption` 键下都可以）。
- 只要英文自然语言、两张图直接传时，实测会把任务当成 multi-reference 重新构图：原图机位和姿态全丢，多视图设定稿还会被拼成两个人。**结构化 caption 不是可选项。**

## 2. 骨架

```json
{"short_description":"一句话：谁、什么姿态、在什么环境",
 "objects":[{"description":"<image_2> 角色的<只改动的那部分> + 与 <image_1> 相同的<其余全部>",
             "location":"在画面的什么位置、什么姿态"},
            {"description":"次要人物/道具，写清只露出哪个部位","location":"画面哪一侧"}],
 "background_setting":"房间、家具、窗、背景元素",
 "lighting":{"conditions":"光的性质","direction":"来自哪一侧"},
 "style_medium":"anime illustration, clean cel shading",
 "composition":{"camera_angle":"eye level","framing":"tight horizontal close-up"},
 "edit_instruction":"Change only <范围>。Give it <要换成什么>。Keep <要原样保留的每一项> exactly as in <image_1>. Do not cover, move, add or remove anything. <image_2> is a <范围> reference only: do not copy its outfit, background, standing pose or other views."}
```

`objects` 里每一项都要写清「哪部分来自参考图、哪部分来自画布」。方位和画面位置写具体（左侧、画面中部、靠近下边缘），
这是让模型留在原构图的唯一抓手。

## 3. 五条硬规则

1. **参考图先裁成单视角。** 多视图设定稿整张喂进去很容易串视角、拼出两个人。裁出正面单人就够（长边 800–1024 足够）。
2. **画布放 `<image_1>`，宽高取画布的宽高比**（按 16 的倍数取整）。
3. **只改该改的部分，并逐项列出要保留的东西。** 「替换整套外观」会让原图的身体状态、姿势、与其他对象的接触全部被重画——
   在编辑类任务里等于换了一场戏。改成「只换头部：脸、发色、发型、发饰、瞳色；身体、皮肤、着装状态、姿势、
   与其他对象的接触全部按 `<image_1>` 保留，不覆盖、不移动、不添加」后，一次过且耗时不变（约 30 s）。
4. **动作与方位必须写明。** 只写「保持两者的接触不变」，模型会画出位置关系似是而非的两块形状；把动作写实
   （在做什么、谁从哪一侧进入、对方在画面哪条边、哪个肢体抬起、相接点大致在画面什么位置）之后，结构立刻合理。
5. **形状、面积、深浅交回 `<image_1>`。** 第 4 条的反面：把局部形状写细（包覆程度、缺口形状、多宽多深）会让模型画出一块和被摄体脱节的形状，
   构图直接错。粒度就是「动作与方位写死，几何交给原图」。

## 4. 常见失败与对策

| 现象 | 原因 | 对策 |
|------|------|------|
| 原图机位、姿态全丢，画面被重新构图 | 只有自然语言、没有结构化 caption | 写 VGL JSON，caption 里把机位/构图/姿态/光源方向写死 |
| 同一个人被画成两个、视角混乱 | 参考图是设定稿或拼图 | 先裁单视角再传 |
| 该保留的身体状态/接触被覆盖 | 指令只写了「换成参考角色的外观」 | 逐项写「keep … exactly as in `<image_1>`，不覆盖、不移动、不添加」 |
| 该可见的位置被布料/衣物盖住 | 只换头也会被模型顺手「整理」 | caption 写清该位置的遮挡关系与可见范围；instruction 明确禁止补衣服、盖布料、移动衣物 |
| 局部形状脱节、像贴上去的 | 过度描述局部几何 | 删掉尺寸/包覆类描述，只留动作与方位 |
| 配饰翻倍（左右各一个、多一个夹子） | 参考图上的小物件被当图案复制 | 明确数量：「one …, on the left side; no second hair clip」 |
| 输出串到参考图的背景/白底/站姿 | 没限定参考图的取用范围 | 结尾固定写「reference only: do not copy its outfit, background or standing pose」 |

## 5. 已验证有效的细节

- 提示词上限够写清楚，不需要为了短而省掉职责说明；英文、句式短、每句一个约束最稳。
- 一次只要求一个主要变更；要同时换人 + 换背景 + 改画风时拆成两轮，把上一轮输出当 `<image_1>`。
- **固定 seed 做单变量对照**：同一版提示词在多个 seed 下都能出合理结果，差别只在细节（相接处深浅、配饰数量）。
  调 seed 是细调手段，不能替代把动作写清楚。
- 服务端固定 4 步 / guidance 1.0，改这两个参数不在本部署的验收范围内；变量留在提示词和输入图上。

## 6. 验收清单

1. 尺寸等于 `--width/--height`，人物数量与道具数量不变，没有多出的人物、文字、水印。
2. 画布项（机位、构图、姿态、背景、光向）与 `<image_1>` 对得上。
3. 改动项（脸、发型、发色、发饰、瞳色）与 `<image_2>` 对得上，且原图的对应元素没有残留。
4. 逐项检查高风险残留区：原发型边缘、发饰、领口、手腕、腰间、裙摆/衣摆、腿部绑带。
5. 逐项检查「不该动的地方」：身体状态、与其他对象的接触、对方身上的东西，全部和 `<image_1>` 一致。

## 7. 已知链路瑕疵（不是提示词问题）

肤色整体偏白（参考角色本身偏白时更明显）、原图的柔和阴影被轻微压平、参考图的服饰细节会小范围串味
（例如领口样式被带成胸前的配饰）、手指可能偏粗。这些用提示词只能压低发生概率，要根治得换 checkpoint 或调采样配置。
