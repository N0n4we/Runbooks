# 多图编辑提示词：角色替换与属性迁移

适用于 `QwenImage21Pipeline`（Qwen-Image-2.1 / 2.1-Turbo，服务端 8 步、CFG=1、无 negative prompt、无 mask）。目标是「改对指定的东西，其余保持不动」，而不是重画一张像参考图的画。

## 1. 模型怎么看你的输入

- 每张参考图按**传入顺序**变成 `<image1>`、`<image2>`……：既进文本编码器的视觉上下文，也被 VAE 编成 latent 拼在噪声前面。
- 提示词里没有 `<imageN>` 时，文本和图像之间**没有任何绑定**。模型会退化成「编辑第一张图、其余图当弱参考」，表现为几乎原样返回 + 轻微改色。
- 所以 `<image1>` 的编号必须和 `--images` 的顺序一致。引用了没上传的编号会被服务直接拒绝。

## 2. 四条硬规则

1. **每张图都要有标签和职责。** 一句「以 `<image1>` 为画布……用 `<image2>` 只提供 X」比十句形容词管用。官方 editing 规范明确禁止「图1 / 第一张图 / image A」这类自然语言指代。
2. **画布图放第一位。** 画布 = 保留背景、构图、机位、光线、姿态的那张；`--width/--height` 按画布的宽高比传。参考图整张（包括多视图设定稿）可以直接用，但要在提示词里写「只取其中一个视角，不复制多视图排版/背景/站姿」。
3. **身份和造型「指图」，不要用文字重述长相。** 用文字描写脸和发型会让模型按文字重画一个人，一致性和细节都会掉。文字只负责三件事：改什么、保留什么、原图中哪些具体元素必须消失。
4. **只写「整体替换」会留下原图元素**（原发色、原发饰、原服装的某个部位）。必须点名这些部位，并说明它们被替换成什么。

## 3. 提示词骨架

```text
以 <image1> 为画布：保持 <image1> 的<背景/构图/机位/光线/人物姿态与相对位置>完全不变。
将 <image1> 中<对象>的身份和服装整体替换为 <image2> 中的角色：脸部五官、发型、发色、发饰和整套服装全部沿用该角色的外观，<必须呈现的穿着结果>。
原图中的<必须消失的具体元素：原发色、原发饰、原服装的某个部位>全部换成 <image2> 里的这套外观。
<image2> 只用于角色身份与造型参考，只取其中一个视角，不复制它的背景、多视图排版和站姿。
保持原有<画风：动漫插画 / 摄影 / 3D>，画面中<人物数量>不变，不添加任何文字。
```

变体：

- **换背景**：`<image1>` = 主体图（画布），`<image2>` = 场景；写「保留 `<image1>` 的人物、姿态与光线方向，背景替换为 `<image2>` 的场景，人物与地面接触位置和透视保持一致」。
- **换部分物件**：`<image1>` = 画布，`<image2>` = 物件；写「只把 `<image1>` 的 A 换成 `<image2>` 的 A，其余画面保持原样」。改动越局部，越要点明边界。
- **合成/双人**：所有图都是身份来源，`ratio_follow` 由画布图决定；逐个描述「`<image2>` 的人物站在左侧、`<image3>` 的人物站在右侧」，并写「各自独立保留身份，不互相串用脸、发型和衣服」。

## 4. 常见失败与对策

| 现象 | 原因 | 对策 |
|------|------|------|
| 输出几乎等于原图，只轻微改色 | 提示词里没有 `<imageN>`，或只写了「替换为参考图里的角色」 | 加标签 + 写明每张图职责 + 点名要消失的原图元素 |
| 参考图被无视，脸/衣服都还是原图的 | 同上，或文字重述了人物长相 | 身份只用「沿用 `<image2>` 的外观」，删掉外貌形容词堆砌 |
| 原发饰、原服装残留在新造型上 | 只说了「换掉」没说是哪一件 | 具体点名部位，并写「画面里只保留这套新服装」 |
| 输出变成参考图的排版（多视图、白底、站姿） | 参考图是设定稿/拼图，且没限定取用范围 | 加「只取其中一个视角，不复制多视图排版、背景和站姿」 |
| 构图整个被参考图接管 | 额外塞了一张特写/胸像作为参考 | 不要用特写当参考；要更清楚的脸就换更清晰的角色图 |
| 多出一个人、多了文字 | 人物数量和文字没约束 | 结尾固定写「画面中人物数量不变，不添加任何文字」 |

## 5. 已验证有效的写法细节

- 中文提示词完全可用；**`<imageN>` 标签与语言无关，多图任务必须写**。服务端接受 `<image_1>` 兼容写法并转成 `<image1>`，但新写的提示词统一用 `<image1>`。
- 用肯定句写保留项（「保持背景与 `<image1>` 完全一致」），比一串「不要……」稳定。只有「原图中必须消失的元素」适合写成否定。
- 一次只要求一个主要变更。换人 + 换背景 + 改画风混在一段里时，优先拆成两轮，把上一轮输出当 `<image1>`。
- 提示词上限 16384 字节；够写清楚，不需要为了短而省掉职责说明。
- 服务端固定官方 8 步采样表、`true_cfg_scale=1.0`，所以 `negative_prompt` 不生效，改步数也不会覆盖采样表。**不要指望调参救提示词**；把变量留在提示词和输入图上，seed 固定，才能判断哪一句起了作用。

## 6. 验收清单

1. 输出尺寸 = 传入的 `--width/--height`，只有一个人物/一件主体，没有多余人物和文字。
2. 画布项（背景、构图、机位、姿态）与 `<image1>` 对得上。
3. 参考项（身份、发型、服装）与 `<image2>` 对得上，且**没有原图元素残留**。
4. 逐项看原图的「高风险残留区」：发饰、领口、腰间、裙摆、手上的饰品、腿部绑带。
5. 只改提示词的对照实验要固定 seed，方便判断差异来自哪一句。

## 7. 已知链路瑕疵（不是提示词问题）

8 步 Turbo + CFG=1 下，平坦区域（床单、墙面、皮肤）偶发极淡的竖向条纹，局部布料收口也会不自然。这类现象调提示词无效，可换 seed 或多出一张再筛；要根治只能换非 Turbo checkpoint 或调整采样配置（那已超出本部署的验收范围）。
